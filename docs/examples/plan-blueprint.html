01 · Plan 负责什么

记录需求范围、实施步骤、风险和完成标准。后续执行以这份契约为依据；图中流程应能在 Plan 里找到对应说明。

02 · HTML 帮助核对什么

把入口、关键判断和结果画出来，让用户能检查是否遗漏分支。图中名称、范围与验收项需要和 Plan 一致。

04 · 通过后做什么

方案确认后进入 Worktree 预检，先展示真实 dry-run，核对目标路径、分支和创建计划，再进入创建授权。

05 · 需要调整时怎么处理

在批准方案前返回讨论，补充遗漏或修改口径；重新生成 Plan 与 HTML 后，再进行同一套验收。

06 · 创建授权的边界：方案通过验收后仍需核对 Worktree 预检，并由用户单独批准创建；后续代码执行属于下一阶段。

按这三个结果验收

文档是否一致
Plan 与 HTML 描述的是同一需求，节点名称、范围、分支和完成标准相互对应。
分支是否完整
通过后能进入预检；需要调整时能回到讨论，更新方案后重新验收。
授权是否清楚
先查看预检结果，再批准创建 Worktree；方案通过不等于已经执行代码。
